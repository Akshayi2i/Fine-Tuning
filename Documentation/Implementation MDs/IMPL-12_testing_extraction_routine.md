# IMPL-12 — Testing / Extraction Routine (CLI Harness)

> Current specification, aligned with the code of 2026-11-24. Dated history: `changelog/IMPL-12_testing_extraction_routine.changelog.md`.

> Read `IMPL-00_MASTER_CONTEXT.md` first. Dependencies: IMPL-01, IMPL-02, IMPL-03 (OCR), IMPL-07 (inference core), IMPL-08 (metrics, the golden eval), IMPL-09 (calibration), IMPL-11 (serving pipeline), IMPL-16 (the production service).
>
> **Naming hazard (master §0.1):** the architecture's "**Fideon SPEC_12**" is the external multi-tenant deployment spec. This file is our testing harness. Different documents.
>
> **Architecture:** `Documentation/Architecture/finetuning-architecture-v2.8.docx` (the extraction/testing routine, folder placement, serving format: the adapter on the bf16 base, confidence without ground truth).

## Goal

A CLI harness that runs any model version - the untuned base, the base with a training checkpoint applied, or a release `vN` - over documents the pipeline has already imported and OCR'd, and writes per-document JSON, per-field and overall confidence, and quality metrics, in one folder per model and run.

It reads every document through serving's own code; it never has an extraction path of its own. It can read in two ways (review R1, decision 2026-11-24):

| Path | How the document is read | What its number means |
|---|---|---|
| `harness` (default) | `serving.pipeline.extract` in `--mode` (`ocr_plus_image` by default, or `image_only`), identity calibration: every field flagged for review | the model's reading |
| `as_served` (`--as-served`) | image_only, the release's calibrators and thresholds, the answer held to the document's stored page text - by the gate's own reading, `evaluation.golden_eval.read_as_served` - plus the **fields-first** result by production's `serving.fields_first.verify_fields` | what production serves; comparable with the gate's number |

**Production reads the `as_served` way** (IMPL-16: fields first, image_only, then the full text). Where `as_served` still differs from production: the stored page text (MinerU's, from the OCR stage) stands in for the text production's served MinerU reads; the line of business comes from the gold's label metadata, where production is told it by the caller; the serving thresholds of `configs/inference/vllm_serving.yaml` (`serving_thresholds`) are not passed, as the gate does not pass them; and the final result is the gate's - the answer held to the page text and its confidence computed again - without the full-text tier and the `likely_missed` / `role_mismatch` flags that production's `add_full_text` adds after it.

## Deliverables

### 1. Folder layout under `testing/`
```
testing/
├── run_extraction.py            # the CLI (also reached as `orchestration.run extract` and `release-check`)
├── compare_models.py            # base vs base + adapter vs gold, per document (§6)
├── comparison.py                # field-by-field comparison, the all-fields report, Excel workbooks
├── testing_record.py            # copies a run's test_record.csv rows into the team's workbook
├── render_prompts.py            # writes prompts/ from common.prompts
├── latency_check.py, extract_server.py, extract_client.py, image_cost_probe.py, write_speed_probe.py   # §7
├── prompts/                     # reference renders of the prompts serving sends (generated, §2)
├── ocr_cache/                   # page images fetched from processed/ in Blob, kept between runs
├── results/{version}/{run_id}/  # OUTPUT: run.json + {doc}.json (+ {doc}.fields_first.json, as served)
├── results/extraction_registry.json   # every extraction, with its run id (§5)
├── results/comparisons/         # compare_models runs, downloaded from Blob (§6)
├── metrics/{version}/{run_id}/  # OUTPUT: run.json + {doc}.metrics.json + summary.json
├── metrics/{version}/test_record.csv  # one row per document read, every run, with its Run ID
└── test_data/                   # git-ignored; read by no code: documents enter by import + OCR
```
**One folder per run** (review R2): `run_id` is the UTC time the run started and its mode, with `-as_served` on an as-served run (`20261124T093112Z-image_only`, `20261124T093112Z-image_only-as_served`; `-2`, `-3` ... when another starts in the same second), so a second run never writes over the first. `run.json`, in both of a run's folders: run id, model tag, adapter, format, mode, `path` (`harness` or `as_served`), `calibration` (`identity`, or which release's calibrators), tenant, corpus, split, document count, `prompt_hash()`, window plan, git commit, start time; at the end, finish time and the counts. Written whole (a temporary file, then a rename).

### 2. `testing/prompts/*.prompt.txt`
Generated by `python -m testing.render_prompts --write`, never hand-edited; `--check` (CI) fails when a file differs from a fresh render, is missing, or is left over. They are not prompt input: regenerating them never changes `prompt_hash()`.

- **Policies: the window prompts serving sends.** Every policy is read in windows (IMPL-11), so a line's reference files are its windows: `policy_<line>.<group>.prompt.txt` and `.image_only.prompt.txt`, for every group `common.schema_sections.groups_for(line)` returns (`decl`, `arrays`, `forms`; `lineblk` on `gl`, `boppr` and `wc`), for every line of `REFERENCE_WINDOW_LINES`: the seven personal lines of `common.schemas.SNAPSHOT_LINES` and the commercial lines `gl`, `bopgl`, `boppr`, `wc`. Under the fast format a file shows what the model reads: the system prompt, a line standing for the window's pages, then the group's request.
- `policy.prompt.txt`: the whole schema, kept as the one whole-schema reference a test reads; its banner says serving never sends it.
- One per ACORD form (25, 125, 140) and one for Loss Runs, each in both modes.

Each holds the role framing, the **schema slice injected from the IMPL-01 registry**, the rules, and the mode's evidence line. The harness does not read these files: it renders through `common.prompts` inside serving, as serving does. `test_prompt_files_match_the_renderer` asserts the files equal the renderer's output. The extraction path never imports `common.aliases` (mapping labels to keys is the model's job; `tests/test_no_runtime_aliases.py`).

`Documentation/Prompts/` holds only a pointer here.

### 3. `testing/run_extraction.py` — the CLI

```bash
python -m testing.run_extraction --model v2   --tenant T --split test --corpus v1              # the model's reading
python -m testing.run_extraction --model base --tenant T --split test --corpus v1              # zero-shot baseline
python -m testing.run_extraction --model base --adapter <run>/checkpoint-280 --tenant T --split val --corpus v1
python -m testing.run_extraction --model v2   --tenant T --source-ids policy_0001 --mode image_only
python -m testing.run_extraction --model v2   --tenant T --split test --corpus v1 --as-served  # as production serves
python -m orchestration.run extract --model v2 --tenant T --source-ids policy_0001 policy_0002   # the same CLI
python -m orchestration.run release-check --version v2 --tenant T --corpus v1                    # = extract --as-served, --split test
```

- `--model` resolves through IMPL-02 `resolve_model_version`; the user names a tag, never a path:

  | Value | Resolves to |
  |---|---|
  | `base` | Untuned `Qwen/Qwen3-VL-8B-Instruct` at the pinned revision, **no adapter** |
  | `base` + `--adapter <folder>` | The base with that LoRA applied on every request, **not merged** - a `checkpoint-N` or a run's adapter folder, local or a Blob prefix (copied once to `/workspace/adapters`). Refused with any other `--model`, without `adapter_config.json`, above the engine's `max_lora_rank`, or with `enable_lora: false`. Results are filed under `base+<run>-<checkpoint>` or `--label` |
  | `v1`, `v2`, … | The base with that version's policy adapter applied per request, staged or published - nothing is merged (decision 2026-10-23). A staged version loads the checkpoint its selection chose, else its latest one with a warning, else it is refused; a version trained on another base than the configured `model_id@revision` is refused |
  | `v2` + `--format fp8` | Refused for the policy adapter: it is a LoRA on the bf16 base, so there is no FP8 model (GGUF is a category error: the harness runs vLLM) |

  `base` is the zero-shot baseline of the pilot protocol (IMPL-15) and the day-zero pre-annotation path (IMPL-04): one implementation for all three.
- **Which documents:** `--source-ids …`, or `--split train|val|test` with `--corpus vN` (that manifest's `source_ids_by_split`); with neither, every labelled document of `--doc-type` (default `policy`) for `--tenant`. `--limit N` keeps the first N.
- `--mode ocr_plus_image` (the default) or `image_only`.
- `--as-served` reads image_only (any other `--mode` is refused) with the calibrators and thresholds of `--release` (default: `--model`; with `--model base` it must be named), loaded as serving loads them (`serving.release_router.release_for`, `serving.vllm_entrypoint.load_release_calibration`). A release with no calibrators is read with identity, as serving falls back, and `calibration` says so. `--release` without `--as-served` is refused.
- **Scoring is on by default:** a document whose gold in `golden-labels/` has a review record (decision 2026-10-22) is scored; one without a gold, or whose gold has no review record, is extracted and not scored - its metrics file says why (`ground_truth: not scored: …`) and `summary.json` lists it under `not_scored`. `--no-score` extracts without comparing.
- `--round` names the Training Round its testing-record rows are filed under (default: the model's tag). Also `--label`, `--format`, `--tenant`.
- **Exit code** (review R3): 1 when any document failed, or none was read; `--allow-failures N` allows N. The last line printed: `read X, scored Y, failed Z, not scored W … passed|FAILED - run <run_id>`.
- On the pod it runs detached in tmux, like every long job.

**What it does, per document:**
```
  1. Read          page count from processed/…/ocr_meta.json; every page image (cached in ocr_cache/);
                   MinerU's page markdown (not read on the harness path under image_only); the label
                   metadata (acord_form, lob: classic auto read as personal auto) and the gold, read
                   under the form-edition rule on common-model lines, as the golden eval reads it
  2. Read it       harness:   serving.pipeline.extract (StaticClassifier: the type is known; windows over
                              every page, merged; identity calibration; ReadSettings.testing():
                              an invalid answer kept, flagged)
                   as_served: evaluation.golden_eval.read_as_served - extract image_only with the
                              release's calibrators, then golden_eval.borrowed_printed_check (the answer
                              held to the stored page text: a value no page prints taken out) and its
                              confidence computed again on that text; then the fields-first result:
                              serving.fields_first.verify_fields on the model's answer, the pages it
                              cites read from the stored text (StoredText)
  3. Write         results/{version}/{run_id}/{doc}.json (with all_fields), {doc}.fields_first.json
  4. Score         against the gold -> metrics/{version}/{run_id}/{doc}.metrics.json; the registry row
                   and the test_record.csv row
  5. Summarise     metrics/{version}/{run_id}/summary.json; a failed document is listed and counted,
                   the batch carries on
```
A document is never read by code of the harness's own: steps 2's functions are serving's and the gate's.

### 4. What is written

**`results/{version}/{run_id}/{doc}.json`** - the serving output contract (`ExtractionResult.as_dict()`: `extraction`, for a policy the canonical JSON with every key of its line's schema; then `fields`, `list_fields`, `line_of_business`, `pages_used`, `review_flags`, `route`) with **`all_fields`** after `list_fields` (`testing.comparison.field_report`): every field of the schema, each with its `value` and `status` (`extracted`, `null`, `no_rows`, `not_in_output`, `system`, `structural`), a written value's `confidence` and `page_ref`, its review `flags`, and against a gold its `gold` value and `result` (`correct`, `wrong`, `missed`, `invented`, `empty`); plus a `summary` of counts and the `document_flags`. Values no page prints are null (printed values only, decision 2026-10-24; strict mode), flagged `<path>:not_printed_removed`. On the as-served path, **`{doc}.fields_first.json`** is the same contract for the fields-first result, written only when it could be served (some cited page has text): a value its cited pages do not print is held back, flagged `<path>:pending_full_text`.

**`metrics/{version}/{run_id}/{doc}.metrics.json`:**
```json
{
  "document": "policy_0001", "model_version": "v2", "doc_type": "policy", "mode": "image_only",
  "path": "as_served", "calibration": "release v2 (bf16)",
  "schema_valid": true, "overall_confidence": 0.88, "pages_used": [1, 2, 3],
  "review_flags": ["coverages[3].limit:merge_conflict"], "text_coverage": null,
  "fields": {"policy.policy_number": {"value": "...", "confidence": 0.94, "correct": true}},
  "field_exact_match_rate": 0.91, "field_normalized_match_rate": 0.93,
  "field_accuracy_by_field": {"...": "..."}, "list_field_f1": {"coverages": 0.88},
  "list_field_recall": {"coverages": 0.83}, "missed_rows": {"coverages": 2},
  "failures": [{"field": "policy.expiration_date", "expected": "...", "got": "..."}],
  "fields_first": {"served": true, "values_held_back": 2, "schema_valid": true,
                   "field_exact_match_rate": 0.88, "field_normalized_match_rate": 0.90}
}
```
`fields_first` is on as-served runs only; `{"served": false, "why": …}` when no cited page had text (production then serves nothing before the full text). `printed_check: "not held: …"` marks an as-served document with no page text to hold its answer to (the gate counts such a reading unscored). Correctness is IMPL-08's - `score_fields`, `score_all_list_fields`, `values_agree` for each field's `correct` - the same definition as the gate: the gold narrowed to what the line's schema holds (`common.canonical.schema_label`), system-filled fields left out of both sides; on a common-model line both sides narrowed, ids compared through what their links name (`common.structural_ids.comparable_for`), table values scored (`core_for_scoring`), and links, codes and overflow numbered apart (`CommonModelTally`: `reference_accuracy`, `coverage_code_accuracy`, `coverage_code_recall`, `additional_fields_recall`, `additional_fields_precision`). The full-text tier is never scored. Without a gold: `"ground_truth": "not supplied — confidence reported, accuracy not measurable"`.

**`metrics/{version}/{run_id}/summary.json`:** `run_id`; `counts` (`read`, `extracted`, `scored`, `failed`, `not_scored` - what each mean is over: confidence and latency over the extracted documents, field match over the scored ones; a failed document is in no mean); schema-validity rate, mean confidence, mean latency, documents needing review, per-type and per-mode counts, the failed documents with their errors, `not_scored`; over the scored documents, mean field normalized match and mean list-field recall; `mean_text_coverage`, `min_text_coverage`, `documents_below_full_text` (under `FULL_TEXT_COVERAGE` = 0.99, chosen, not measured) and `documents_without_full_text`; on as-served runs, `fields_first` (documents served first and not, values held back, and their mean field normalized match). **The file compared across versions** - on the as-served path, comparable with the gate.

**Confidence without ground truth:** even with no gold the routine emits `overall_confidence` and per-field confidence. On the harness path it is the identity transform of the raw signal and every field is flagged; on the as-served path it is the release's calibrated confidence.

### 5. `testing/results/extraction_registry.json`
One row per extraction, appended by `append_registry` after a document's results and metrics are written, the file written whole; a failed document writes none:
```json
{"extractions": [{"document": "policy_0001", "doc_type": "policy", "model_version": "v2",
  "run_id": "20261124T093112Z-ocr_plus_image", "quant_format": null, "mode": "ocr_plus_image",
  "result_path": "results/v2/20261124T093112Z-ocr_plus_image/policy_0001.json",
  "metrics_path": "metrics/v2/20261124T093112Z-ocr_plus_image/policy_0001.metrics.json",
  "overall_confidence": 0.88, "schema_valid": true, "review_flags": [], "extracted_at": "2026-11-24T09:31:40Z"}]}
```
`model_version` is the tag that resolves to a `run_manifest.json` (IMPL-02): a result traces to the corpus version and git commit that made its model. Each document also adds a row to `metrics/{version}/test_record.csv` (round, date, split, carrier, line, pages, field match, latency, tokens, Run ID); `python -m testing.testing_record --model <tag> --xlsx <workbook>` copies new rows into the team's workbook, never twice.

### 6. `testing/compare_models.py` — base vs base + adapter
```bash
python -m testing.compare_models --input policy.pdf --gold policy_gold.json --lob homeowners \
    --reviewer-id <reviewer> --review-date YYYY-MM-DD --adapter <checkpoint-N>
python -m testing.compare_models --input data/bundles/<document>/ --adapter <adapter folder>
python -m testing.compare_models --input <folder of document folders> --adapter <adapter folder>
```
- `--input`: a PDF (with `--gold` and `--lob`), a bundle folder (`document.pdf` + `golden.json` + `metadata.json`), or a folder of them. Each is imported and OCR'd under its own tenant (`compare` by default, never `default` or the real data's); a re-run finds it by checksum. A gold is compared only with a review record: a PDF's `--gold` takes `--reviewer-id` and `--review-date`; without one the answers are compared with no gold.
- One model load; each document extracted twice through `serving.pipeline.extract`, by the base alone and with the adapter applied, not merged. No calibrators.
- Per document under `--out` (default `testing/results/comparisons/<label>-<stamp>/`): `document.pdf`, `gold.json`, `base.json`, `adapter.json`, both `*.all_fields.json`, and `comparison.xlsx` (table rows matched by identifier, not position); across documents `summary.xlsx`, and `errors.json` when a route failed. Uploaded to `exports/{tenant}/comparisons/{run}/` (the raw container), checked file by file, removed from the pod unless `--keep-on-pod`; the command prints the `azcopy` line that downloads it.

### 7. The server-path tools
Not the routine above: they read PDFs through a served model (`vllm serve`, `inference_core/openai_backend.py`) and a served MinerU 4 API at the pinned version and tier (`--any-mineru` for timing only).
- `latency_check.py`: times render, OCR, model and total per document; `--runs standard,fields-first` reads each both ways (`fields` scored as first served, then the final result); `--repeat` reads every document twice and writes `run_to_run.json`; scores against gold JSON when found.
- `extract_server.py` (pod) and `extract_client.py` (laptop): a job server behind the pod's proxy and its client; `--fields-first` makes a job `fields_ready` before `done`. The client exits 1 unless every document was read in full.
- `image_cost_probe.py`, `write_speed_probe.py`: short probes of an already-served model.

## Constraints
- Same prompts and same pipeline as serving and the gate - reuse, never reimplement.
- Confidence emitted even without ground truth.
- Documents are read from the OCR the pipeline wrote (`processed/`), by the pinned MinerU (IMPL-03); the harness does not re-check the pin.
- No PII in logs; `results/`, `metrics/`, `ocr_cache/` and `test_data/` are git-ignored, and comparison runs leave the pod through the raw container only.

## Acceptance checklist
- [ ] `run_extraction --model v2 --split test --corpus v1` writes `results/v2/<run_id>/*.json` with `run.json`; a second run writes a second folder.
- [ ] `--model base` runs the untuned base; `--model base --adapter <checkpoint>` applies the LoRA per request, not merged; `--adapter` with any other `--model` is refused.
- [ ] `orchestration.run extract` passes its arguments to `run_extraction.main`; `release-check` is `extract --as-served` with `--split test`.
- [ ] `--as-served` gives the same answer object as the gate's reading of the same stored document, and writes the fields-first result beside it (`tests/test_as_served.py`).
- [ ] `--mode image_only` runs with no OCR text sent and still extracts.
- [ ] Per-field and overall confidence present with and without ground truth; `line_of_business` in every result.
- [ ] With a reviewed gold, per-doc and summary metrics including list-field recall; a gold with no review record is not scored, and says why.
- [ ] Every result carries `all_fields`.
- [ ] The run exits 1 when any document failed, unless `--allow-failures` covers it.
- [ ] `extraction_registry.json` links result → model version → run manifest.
- [ ] `testing/prompts/*.prompt.txt` equal a fresh render (`render_prompts --check`), and cover every trained line's windows in both modes.
- [ ] `compare_models` writes both JSON answers, both `all_fields` reports and `comparison.xlsx` per document, `summary.xlsx` across them, and uploads the run.
